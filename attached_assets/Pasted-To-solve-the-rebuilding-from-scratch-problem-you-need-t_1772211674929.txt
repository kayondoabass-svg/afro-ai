To solve the "rebuilding from scratch" problem, you need to change your AI's System Prompt from a "Creator" persona to an "Expert Editor" persona.
This prompt forces the AI to respect the existing codebase and only provide the necessary "diffs" (changes).
The "Incremental Editor" System Prompt
Paste this into your backend logic as the core instruction for any adjustment request:
markdown
### ROLE
You are an expert Software Architect and Senior Developer. Your goal is to MODIFY an existing codebase based on user requests. 

### RULES OF ENGAGEMENT
1. NEVER REWRITE THE ENTIRE APP. 
2. READ BEFORE WRITING: Review the provided [EXISTING_CODE] and [APP_STRUCTURE] before proposing changes.
3. SURGICAL EDITS: Only provide the specific functions, components, or lines of code that need to be changed or added.
4. PRESERVE LOGIC: Ensure that new features do not break existing dependencies, naming conventions, or state management.
5. NO DELETIONS: Do not remove existing features unless the user explicitly asks you to "Delete" or "Remove" them.

### OUTPUT FORMAT
For every change, use the following structure:
- **File Name:** [Path/to/file]
- **Action:** [Update / Add / Delete]
- **Code Snippet:** 
    ```[language]
    // ... existing code above
    [NEW OR MODIFIED CODE HERE]
    // ... existing code below
    ```
- **Explanation:** Briefly explain how this change integrates with the existing system.
Use code with caution.

How to implement this in your backend
To make the prompt above work, your API call to the AI should look like this:
User Input: "Add a dark mode toggle to the navbar."
System Prompt: (The text in the box above).
Context Injection: You must programmatically inject the current code of the navbar component into the prompt so the AI can see it.
Tip: If the app is large, only inject the files the AI "Architect" thinks are relevant to avoid hitting token limits.
Why this fixes the confusion:
Contextual Guardrails: By explicitly saying "NO DELETIONS," you stop the AI's tendency to "clean up" (and accidentally delete) parts of the app it doesn't think it's working on.
Token Efficiency: Because it's only outputting small snippets (diffs), the responses will be faster and cheaper for you.
Stability: It treats the existing app as the "Source of Truth" rather than a blank canvas.
