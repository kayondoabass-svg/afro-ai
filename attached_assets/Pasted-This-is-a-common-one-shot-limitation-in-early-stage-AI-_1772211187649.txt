This is a common "one-shot" limitation in early-stage AI builders. The AI "forgets" the existing architecture and treats every new request as a blank slate. To fix this, you need to transition from generation to incremental modification.
Here is how you can technically solve this for your platform:
1. Implement "Context-Aware" Architecture
The AI rebuilds from scratch because it doesn't "see" the current code in its active memory.
Codebase Indexing: Before the AI processes a change request, have a background process "read" the existing files and create a structured map (like a JSON file or a Knowledge Graph) of the app’s current state.
The "Context.md" Strategy: Automatically maintain a hidden file that summarizes the app's rules, naming conventions, and core features. When a client asks for a change, feed this file to the AI first so it knows what not to break.

2. Move to "Diff-Based" Updates
Instead of asking the AI to "Build the app with a blue button," change your prompt logic to:
Surgical Edits: Use "Incremental Coding Instructions." Tell the AI it is only allowed to output the code diff (the specific lines that change) rather than the whole file.
Search & Replace: Use a "Coding Agent" workflow that identifies the specific file and function needing adjustment, reads only that section, and applies the fix locally.

3. Use Version Control as a "Memory Bank"
Integrating a hidden Git repository for every project is the best way to handle "undoing" and "adding on."
Restore Points: Before any AI change, trigger a git commit. If the AI messes up the adjustment, the system can automatically roll back to the "Working" state.
Micro-Commits: Every small adjustment should be its own commit. This allows the AI to look at the git log to understand the history of how the app was built, preventing it from getting confused by previous logic.

4. Transition to a Multi-Agent Workflow
Don't use one AI for everything. Split the work:
The Architect (Manager): Analyzes the client's request and decides which files need changing.
The Developer (Worker): Receives only the relevant code and the specific instruction to "Add X to this file."
The Reviewer (QA): Compares the old code with the new code to ensure the AI didn't delete the existing features.
